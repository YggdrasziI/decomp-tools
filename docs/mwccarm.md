# mwccarm (Metrowerks, Nintendo DS / ARM): source forms by symptom

Every entry below was proven on a function of one of three matching decompilations: **ts2-castaway** (game code mwccarm 2.0, base ... sp2, built with 2.0/sp1p5; MSL / runtime 2.0/sp1p2; NitroSDK and NitroSystem 1.2/sp2p3), **dqmj2** (libraries 2.0/sp2p2 or later, game code 2.0 family, built with 2.0/sp2p2) and **dqmj2p** (nothing recorded yet). All the code concerned is ARM mode, mostly C++ for the game code and C for the libraries. The full text, with scores and dates, is each project's `notes/MATCHING.md` (and `notes/COMPILER.md` for the compiler internals); this file only condenses them. Format: **symptom** -> source form -> proof (project, function or unit as the notes name it), then `[source-level]` (a lever of the C/C++ text that may hold on another Metrowerks back end), `[ARM]` (depends on the ARM back end) or `[source-level?]` (unsure). "Hypothesis" marks what the notes themselves do not hold as proven.

## Register allocation and declaration order

- **Two saved registers swapped between two locals** -> swap their declarations: locals get virtual register numbers in reverse declaration order, the first declared is colored first and takes the lower register, a local declared later a higher one -> ts2-castaway `func_0207e2f4`, `func_01ffa538`. `[source-level]`
- **Two saved registers swapped around a call result** (`r5` / `r6`) -> declare the later-assigned local first, without initializer, and assign it after the other (`T *p; U *f = g->fish; p = ...;`) -> ts2-castaway `Unk0203b3b8::func_0203bc24`, `func_02018de4`. `[source-level]`
- **Loop locals one register off around a call result** -> declare the other locals without initializer before the one the call initialises, then assign them -> ts2-castaway `func_01ffa838`, `Unk02005ad4::func_18`. `[source-level]`
- **Loop counter and a pointer swapped** -> declare the counter (or list cursor) before the local taking a call's result, or the pointer at the top of the function before the index, whichever the original shows -> ts2-castaway `func_02060080`, `func_0204b984`. `[source-level]`
- **Pointer used in a loop body takes the counter's register** -> declare it at function scope before the `for`, not inside the loop -> ts2-castaway `func_0202171c`. `[source-level]`
- **Counter in the wrong saved register** -> declare it at the top (`int i;` then `for (i = 0; ...)`) instead of in the `for`; two loops continuing from one counter share it the same way -> ts2-castaway `func_02043f0c`, `func_02043b94`. `[source-level]`
- **Second loop's counter and pointer rotated when two loops share one counter** -> `for (int i = 0; ...)` in each loop, a separate `j` for the middle loop, or separate variables per loop; but a counter shared by all cases of a switch is one local at the top -> ts2-castaway `func_01ffadf8`, `func_02092554`, `func_0205c758`. `[source-level]`
- **Nested loops with a running counter in rotated registers** -> declare all of them before the loops and try the orders (`int bit = 0; int x; int y;`; inner index and step before the outer loop; `u32 i; u32 hits; int found = 0; i = 0; hits = 0;`) -> ts2-castaway `func_02059534`, `Unk0202cdf0::func_0202df0c`, `func_02054fbc`. `[source-level]`
- **Locals of one branch take lower saved registers than the function's result** -> declare them at the top, before the result (`int id; int dirKey; int found = 0;`) -> ts2-castaway `func_0205b7e0`. `[source-level]`
- **Registers permuted among several locals, single moves fail** -> hoist every local (nested blocks and `for` headers included) to the top without initializers, then search the orders; the last step is often a type -> ts2-castaway `func_0206ddb4`, `func_020a6d38`. `[source-level]`
- **Declaration order has no effect** -> the locals belong to an inline function (their order is ignored where it is inlined): move the body into the caller with the caller's own locals -> ts2-castaway `func_0208c700`. `[source-level]`
- **Declaration order has no effect on a small unsigned local set from a load** -> a `u16` local stays merged with the load's virtual register; declare it `int` and the order applies again -> dqmj2 `func_02042950`. `[source-level?]`
- **Two locals swapped with every declaration order** -> change one type: `u32` for a value only passed on, `int` instead of `s8` for a sign-extended byte, `u32 kind` for an index -> ts2-castaway `func_14` of `unit_02013258.cpp`, `unit_02005E30.cpp`. `[source-level]`
- **A rotated set of saved registers in a loop, or index and array offset swapped** -> `for (u32 i = 0; (int)i < n; i++)`: the unsigned counter changes the coloring, the cast keeps the signed branch; the other counter of a nest may need the same form -> ts2-castaway `Unk02033ee0::Unk02033ee0`, `func_020647f0`, `func_0205f328`. `[source-level]`
- **Three registers rotated around loop values** -> `const` on the loop's invariant locals (`const int x`, `const int y`); a stack parameter the original loads into a register is `const int w = width;` (a plain local is copy-propagated away) -> ts2-castaway `Unk02047a8c` constructor, `func_02092f50`. `[source-level]`
- **A coloring no declaration order gives** -> reuse a dead local for the new value; the reverse also exists (one local per block instead of one reused variable frees a register) -> ts2-castaway `func_0201c2d8`, `unit_0203FA44.cpp`. `[source-level]`
- **A parameter's register later holds a derived value** -> reassign the parameter (`key = f(key, ...)`, `t = count - 1;`) instead of a new local; the reverse case (parameter and the value written over it swapped) needs its own local: try both -> ts2-castaway `func_02064074`, `func_020a2ce8`. `[source-level]`
- **A flag chained through several calls** -> write every result back to the same variable (the parameter or one local), never a new local for one link nor a nested call -> ts2-castaway four `func_3c` handlers (`Unk0202aef4::func_3c`). `[source-level]`
- **Last swap left after the order search** -> remove a temporary (`rest = a + b - c` instead of `end = a + b; rest = end - c`), or write a repeated subexpression out instead of keeping it in a local -> ts2-castaway `func_020993d8`; dqmj2 `func_02040cd0`. `[source-level]`
- **An expression lacks a free register or picks another one** -> the opposite move, a local: `int n = a - f(); n /= k;`, a table entry read into its own local first, a local for an intermediate result -> ts2-castaway `func_0205c680`, `func_020a1f84`. `[source-level]`
- **A value spilled in the original and recomputed in ours** -> pass the argument through a local (`int k = base + 3; f(k);`) so the compiler keeps `k` and spills the base -> ts2-castaway `func_02018f1c`. `[source-level]`
- **Saved registers rotated over a whole function with a loop in the middle** -> move the loop into a `static inline` helper taking the output pointer and the field by reference (`const int &id`); a second loop whose counter takes new registers goes into an inline function taking copies -> ts2-castaway `Unk02033ee0::func_0203577c`, `func_0208e364`. `[source-level]`
- **A register reused for a constant where the original keeps the local** -> initialise the locals at their declaration; assigned as statements, their registers are reused for `return -1` / `x = 0` -> ts2-castaway `func_0208e364`. `[source-level]`
- **Same flag code, other loop registers around the call** -> `(flags & 1) != 0` against `(flags & 1) ? 1 : 0` for a bool argument -> ts2-castaway `func_0201be00`. `[source-level]`
- **Neighbouring locals swapped next to a default or a two-way value** -> `x = x ? x : c;` against `if (x == 0) x = c;`; `int v = m >= 0 ? m : f();` against `v = m; if (v < 0) v = f();`; a ternary in the argument (`f(o, flag ? actor : 0)`): try both forms -> ts2-castaway `func_02001fdc`, `Unk02050640::func_020514f0`. `[source-level]`
- **Fields unpacked from one word with the masks in another order** -> the declaration order of the locals sets the order of the masks and the registers -> ts2-castaway `func_020a1aa4`. `[source-level]`
- **A stack address hoisted into a register, or a second loop guard, that ours misses** -> use the class local through a pointer alias (`T child = ...; T *c = &child;`) or a pointer bound to the temporary (`c = &(const Cell &)f();`), declared where its register must fall -> ts2-castaway `func_020ab57c`, `func_02005654`. `[source-level]`
- **Order search works only with one more copy** -> initialise a local by re-reading the field rather than by copying the other local, or copy one local into a second one declared at the top (`f2 = f;`) -> ts2-castaway `Unk02050640::func_02051294`, `Unk02033ee0::Unk02033ee0`. `[source-level]`
- **A flag tested twice through one register** (`ands`, then `cmp #0`) -> test `flags & 8` directly in both `if`s rather than through an `int` local -> ts2-castaway `Unk02051da0::func_0c`. `[source-level]`
- **Two registers swapped after a pointer test** -> test the field, copy it to a local only after the early branch -> ts2-castaway `func_020548b0`. `[source-level]`
- **Load order and registers of masked parameters** -> write the parameter masks before the locals that read members; narrow a mask parameter in place right after a second mask is taken from it -> ts2-castaway `Unk0208d304::func_0208d9bc`, `func_01ff924c`. `[source-level]`
- **One parameter in two registers** -> one assignment (`tiles = (tiles << 3) - 8;`) instead of two steps -> ts2-castaway `func_020901a4`. `[source-level]`
- **Identical bit field code, other registers** (`bic bic bic orr` permuted) -> write the field in two statements, clear then OR (`f.seconds = 0; v |= s << 6;`): the store of the cleared value is removed only after coloring, so it gets its own register -> ts2-castaway `func_02019fa0`. `[source-level?]`

- **A truncation flipping between two scratch registers on a repeated statement** (`mov r1, r0, lsl #16` at every fifth or so) -> the code generator ends a basic block at a statement start once it holds more than 100 pcodes; add or remove code-neutral pcodes before the site (a local for a call result, a `u32` local for an index) until the split falls where the original's does -> ts2-castaway `Unk0203ecd4` constructor, `Unk02029b80`. `[source-level?]`
- **Stack objects at the wrong offsets** -> slots go down in order of creation: the first local created gets the highest offset (nested blocks and inlined functions alike), unnamed temporaries come below the named locals; reorder the declarations -> ts2-castaway `func_02097f1c`, `func_02071fdc`; dqmj2 `func_02043938`. `[source-level]`
