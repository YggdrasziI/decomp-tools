# mwccpsp (Metrowerks, PSP / MIPS): source forms by symptom

Every entry below was proven by a matching build with mwccpsp 3.0.1 (build 219, `-O4`) in mhfu-decomp; the full list, with every witness function, is that project's `notes/MATCHING.md` (compiler facts in its `notes/COMPILER.md`). Each bullet reads: symptom in the assembly -> source form that produces it (function that proved it), then a tag: `[source-level]` when the lever is how the C/C++ is written and may carry over to another Metrowerks back end, `[MIPS]` when it depends on the MIPS back end, `[source-level?]` when unsure. "Ours" means the code our source gave before the fix.

## Register allocation and declaration order

- Two locals in swapped saved registers -> the declaration order of the locals sets them; pointer locals take saved registers in the reverse of their declaration order (declared `p`, `item`, `state`: `state` gets `$s0`) (func_088B871C, func_088D08D4). [source-level]
- Two stepped pointers swapped in a counted loop -> declare them in the reverse order (func_088D6924). [source-level]
- Float locals in swapped FP registers -> they take registers in reverse declaration order (func_088A356C). [source-level]
- Stack slots of locals in another order -> declaration order sets the offsets: the first local declared gets the higher offset, local arrays and aligned vectors are placed in reverse declaration order; try the permutations (func_0889AF48, func_088F5C88, func_088D1978). [source-level]
- A scalar and a local struct, or an initialised array and a buffer, with slots swapped -> declare the scalar / the initialised array first (func_08892E7C, func_088B01BC). [source-level]
- Spill slots in the wrong order -> named locals take descending slots in declaration order, compiler temporaries ascending slots below them (func_088F9EF4). [source-level?]
- Many locals, registers wrong -> scripted search: shuffle the declaration lines, then swap pairs while the diff score rises (stack locals kept first so the frame does not move) (func_0887E320, func_08873CC0). [source-level]
- Saved registers swapped and declaration order does not help -> change the order of the assignment statements, or keep the initialisers in the declarations in register order (func_0888D734, func_0888C9F8). [source-level]
- Loop start registers filled in the wrong order after a declaration search -> write the start assignments in the order the original sets the registers, counter included (func_0889C524, func_08882FA4). [source-level]
- Loop pointer and counter in the wrong saved registers whatever the declaration order -> declare both with initialisers in a block around a `do while`: `{ s32 i = 0; u16 *p = ...; do { ...; i++; p++; } while (i < 3); }` (func_0885CF9C). [source-level]
- Several loops, registers shifted from the second loop on -> one counter variable per loop, then permute declarations (func_0887E320, func_088DC40C); block-scoped `s32 i = 0;` per branch (func_088D72A4). [source-level]
- The opposite: a later loop's counter and index take each other's registers -> reuse the counter of an earlier loop, or reuse the first counter for a value of the second loop (func_088D2C14, func_08879198). Not a rule: one function needed one counter for all loops, another one per loop; try both (func_088F6450, func_088F9EF4). [source-level]
- Two loops over one table with counter and pointer in different saved registers -> the second loop gets its own counter and pointer (func_088AC0E8); first of two search loops: its own index declared first, pointer shared (func_088D7904). [source-level]
- Swapped temporaries in one of several same-shaped sections, or nested sort loops -> split each loop variable per section / own counters for the nested loops (func_088A4CB0, func_088D897C). [source-level]
- Counter and pointer stepped together in swapped registers -> both in the `for` header, `for (i = 0, p = table; i < n; i++, p++)`, `i` declared before `p` (func_0889F6A0, func_088A08E4); or a pointer local declared after the counter instead of stepping the parameter (func_0883F8B4). [source-level]
- Counter and pointer swapped in an unrolled clear, or two arrays of one record stepped as two pointers -> pointer(s) declared before the counter, stepped in the body / in the `for` (func_088739A4, func_08874454). [source-level]
- A pointer parameter whose saved register is swapped with a later local or with the first call result -> take it as `void *` and read it through a typed local declared after that local (func_088AE988, func_08890F70). [source-level]
- A parameter copied to its saved register first and tested there -> copy it into a local at the top and loop on the local (func_088A01D8). [source-level]
- Parameters only passed on to calls, saved in reverse parameter order where the original uses first-use order -> declare the parameter `u32` while the callees take `s32`, so every use converts (func_08882D9C). [source-level?]
- Saved registers right only when pointers and integers share locals -> every local `s32` and a scripted search of role-to-local assignments and declaration orders (func_088C6DF8, func_088FB2B0). [source-level]
- The result's constant set before a pointer's last add, pointer in the wrong temporary -> declare and initialise the result first, `s32 ret = -1; T *p = ...;` (func_0885187C, func_0888080C). [source-level]
- Binary search with `lo` / `hi` swapped -> declare `lo` first (func_0890D7BC). [source-level]
- One extra register everywhere, or the last load in the return register although nothing seems returned -> the function returns that value (func_088A4CB0, func_088A7A68). [source-level]
- One saved register too many around `base + i`; an inner counter cleared before the address of the outer element -> no local for the sum or the element, write it at each use (func_08881458, func_088D2C14). [source-level]
- Row offsets and table pointers in lower registers than the loop variables -> they are not variables; index (`D[row][col]`) and let strength reduction create them (func_088F9EF4). [source-level?]
- Whole-loop register colouring different around a record row, declarations without effect -> a `static inline` getter taking a `u8` index, called again in each condition (func_0889E1E0). [source-level]
- A pointer computed before a call and kept in a saved register although used only after it -> a local assigned before the call (func_088D2B90). [source-level]
- Table pointer and computed index swapped in an inline lookup -> put the index in an earlier function-level local not used again, helper indexing `tbl[i]` with no copy (func_088DB608). [source-level?]
- Loop offset, block and size in wrong saved registers -> `for (i = 0, p = 0; ...; i++, p += K)` with a `u32` offset and the constant grouped with the base, then a declaration search (func_088C022C). [source-level]
- Two copies of one loop with different multiplier registers -> one multiplier local per copy, the second declared last (func_08893C6C). [source-level]
- Two loaded values in swapped temporaries in one store, regroupings without effect -> read the value used twice through its own pointer local (func_08893894). [source-level?]
- Byte locals filled from one of two tables in other registers -> declaration order, and the loads written in one order in both branches (`= 0` at the same place in the branch without the field) (func_088DA398). [source-level]
- A result flag that copies a counter's register -> declare it `u8` (func_08880D94). [source-level]
- Gap between two stack locals, or offsets off by 8 with the right frame size -> the array is larger than the bytes used; a `struct` local takes a slot even when it lives in a register (func_0887E320, func_088AD87C). [source-level]
- A local struct 4 bytes too high in the frame -> its real size is larger: trailing padding or unused trailing fields (func_0888A538, func_088709D4, func_088B0FF8). [source-level]
- A stack buffer at an 8-byte boundary where ours is 4 bytes higher -> it holds 64-bit members, declare a `u64` array (func_088B0604). [source-level]
- A stack local passed by address -> an array reaching to the next such local / the frame top, so the frame size matches. [source-level]
- A small buffer that must sit below an initialised array on the stack -> declare it inside the loop body that uses it (func_088F56B8). [source-level]
- The stack slot of a helper's result lower than the slots of later helpers -> write the call as the argument of the next helper; a local in between allocates in source order (func_088D2E18). [source-level]

## Statement and expression order

- A constant stored and then used as an argument from the same register -> assign the local before the member, `lang = 1; p->x = 1;` (func_088902A8). [source-level]
- A constant and a load, or independent set-up statements, scheduled in another order -> the order of the statements decides; separate statements, then permute (func_088AB514, func_088DCB00, func_08893444). [source-level]
- A constant not folded (`li 0xFF` then `addiu -6`) -> two statements, `room = 0xFF; room -= 6;` (func_088A7860); a running offset the compiler folds -> one variable assigned several times, `off = 0; ... off += 0x20;` (func_088A4CB0). [source-level]
- `(s + a) + b` where ours gives `s + (a + b)` -> two `+=` statements; `sum = sum + a + b` is reassociated (func_0888307C). [source-level]
- A multiply by a constant added in the other operand order -> write the factors, `x * 12 * 12 * 12` for 1728 (func_0887E320); a constant added before the base -> parenthesize, `y + ((j / 24) * 16 + 8)`, `extra + (f() + 4)` (func_088F56B8, func_088FCF84). [source-level]
- Compound vs plain assignment changes operand order and extension placement: `p->b = p->b + n` (raw add, extend after) vs `p->b += n`; `val = val + base / 10`; but `p->f += 0.5f` for swapped FP add operands; try both (func_088D5EF0, func_0885CE38, func_0888A538). [source-level]
- Two read-modify-write stores in a row to one field -> two compound statements, `x |= A; x &= ~B;` (func_088A4280, func_088A42F0). [source-level]
- Float multiply with the constant as first operand, loaded after the int-to-float conversion -> `x = n; x = K * (float) x;` (the redundant cast stops the swap) (func_088429EC, func_08841100). [source-level?]
- Float multiply / add operands swapped -> cast the difference `K * (float) (a - b)`, read the table entry into a float local first, `prod = prod * f;` after a float local for the conversion, or a temporary for the quotient before the final sum (func_088B81F8, func_088CF2C8, func_088D08D4, func_0888C294). [source-level?]
- Product of squares in the wrong order -> `a = f - lo; b = hi - f; ... k * (a * a) * (k * (b * b))` (func_0888E634). [source-level]
- Integer multiply with a call result as the wrong operand (`mult v0, v1`) -> the result in its own (unsigned) local first, `n = f(); return n / 10 * t[i];`, `w * scale` (func_0885E664, func_0887D02C). [MIPS]
- Subtraction operands loaded in the other order -> `(s32) (a + 1) - b` (func_08816F24); the two operand loads before a subtract from `f() * 7` -> `w = f() * 7;` at the call (func_08896D24). [source-level?]
- Operand load order of a comparison -> write the first-loaded operand first and flip the operator: `b - 13 > a` loads `a` first unlike `a < b - 13`; `x > tbl[i]` puts the field on the right register (func_088F383C, func_0887A838, func_08871BC4). [source-level]
- Branch operands swapped in a search (`bnel v1, v0` for `bnel v0, v1`) -> `arr[j] == x` vs `x == arr[j]`; the constant before the index in the address, `*(u8 *)(p + 0x676 + i) == c`; the masked load in its own local (func_088932A8, func_088D6A1C, func_08872ED4). [source-level?]
- The second test of a less / greater pair in a saved register -> same operand order with the operator flipped, `if (x[b] < x[a]) {...} if (x[b] > x[a]) break;` (func_089030D8); two byte loads in reverse order -> `if (key[k] < p[OFF + k]) ... if (p[OFF + k] < key[k])` (func_0889C81C). [source-level]
- Field loads grouped before the first compare, or byte loads in the wrong order -> read them into locals first, declared and assigned in the order of the loads (func_0887BB48, func_0889BFA0). [source-level]
- A load placed before / after a call, a store or a pointer chain -> put the value in a local at the place of the original load: index before the store (`idx = p->cur; p->state = 1; f(p, &p->e[idx]);`), global sum before the comparison, call result before the compare (func_088CD230, func_088A0DB8, func_0887CAFC). [source-level]
- A float (helper) result read back after the argument loads of the next call, or FP registers swapped around a call result -> store it in a local first (func_08841100, func_0888D734); a `jal` emitted before an inlined loop whose result is a later argument -> same (func_088F2B0C). [source-level]
- Two tables read with the same index, the second one's value needed first -> read the first table into its local first, then the second (func_088D2E18). [source-level]
- A stack struct filled from arguments with stores or argument loads in the wrong registers -> write the constant store last, swap the two stores that use the stack parameters, else permute the field stores; try plain index order first (func_088801A0, func_0887FFE8, func_088F4210). [source-level]
- One value stored to several places with one load, highest offset first, or a constant register reused -> chained assignment, `m->a[0] = m->a[4] = x;`, `a[0] = a[1] = ... = 5;`, `w = c = K;` (func_088CEE68, func_088F4A7C, func_0882232C). [source-level]
- A table pointer loaded before the index is scaled -> two statements, `rec = tbl[kind]; rec += id;`; nested tables: one pointer step per level; an indexed address in its own register: `t = &t[idx]; e = *t;` (func_0885CF9C, func_08870AEC, func_088C03CC). [source-level]
- A 16-bit key from two bytes with pointers or `or` operands swapped -> two statements on one local, `c = hi[i] << 8; c |= lo[i];` (func_088AEB80, func_088B6E14); a 32-bit value from two halfwords -> load the high half into the result local first, then `v = lo | ((v << 16) & 0xFFFF0000);` (func_088702F0). [source-level]
- A flag or pointer set in the delay slot of a call -> assign it before the call (func_088F012C, func_088FCF84); a parameter copy before the `jal` with a `count = 0` in its slot -> assign the call result before the zero initialisation (func_088A0820). [MIPS]
- A flag cleared / pointer set in the delay slot of a guard branch -> initialise it before the `if`, not inside it (func_08901664, func_088AEC3C); a loop count in the wrong argument register -> read it into its local before the pointer set-up (func_088A2A78). [MIPS]
- A stack argument computed before the one stored below it -> the sum in its own statement before the call, `arg8 += base; f(..., arg8);` (func_08883B54). [source-level]
- A sub-expression computed again where ours shares it -> defeat the sharing: an unsigned constant in the second copy `(row + 1U) * 0x10`, read the operand again in the source, read a count once through a cast and once as the member (func_088F9058, func_088795F4, func_088F4518). [source-level?]
- The opposite, a shared sum kept in a saved register -> write the sum in the same operand order at each use (func_0889C2F0); full expressions repeated in each block are shared by the compiler across inlined copies (func_088F4518). [source-level?]
- A word read once and kept, its mask recomputed for an index -> a narrow local for the tests, the field itself in the index expression (func_088CF2C8). [source-level]
- A float constant loaded once and copied where another local gets the same value -> a local of its own, `one = 1.0f;`, used by name at those places only (func_088D3F68). [source-level]
- `a[i + 1]` loaded before `a[i]` with `a[i]` reused -> `x * (a[i + 1] - (base = a[i]))`; two divisions of the same loads -> compute both before the first store (func_0888C344, func_0888C3AC). [source-level]
- A sum of N halfwords started from a zero register -> N `sum +=` statements, not a loop (func_0887EBFC); two byte swaps loaded together -> two plain three-statement exchanges in a row (func_088D897C). [source-level]
- A modulo index with the count loaded before the divide and stored before the remainder is read -> the new index in a local first, then the count update, then the index store (func_0889F0D8, func_0889F1CC). [source-level]
- A minimum as copy / compare / conditional copy -> `v = len; if (max < len) v = max;`, not `?:` (func_088B040C). [source-level]
- Multi-lane arithmetic with registers or load order off -> one statement per stage, all lanes at each stage (func_088A356C, func_088A2498). [source-level]
- A step whose mask comes after `i++`, or a pointer step before an extension -> order the two statements that way; a separate narrow local for the digit, `d = *p++ - '0'; n = d + n * 10;` (func_0882232C, func_08894B0C). [source-level]
- An end address hoisted and spilled -> `pos = size - 1; buf[pos] = 0;` (func_08893C6C); one reload too many through `*slot` -> reload once into the local (func_0888FDFC). [source-level]
- Mask operands swapped (`and v1, load, mask`) -> read the byte into a `u8` local first (func_08872444). [source-level?]
- A result stored to the stack just before the epilogue and never read -> a dead `val = f(..., val, ...)` on an address-taken local (func_08883FF0, func_088846F4). [source-level]

## Types, signedness and casts

- Sign-extension or signed/unsigned load differences against decompiler output -> counters and parameters were plain `int`, truncated at the store or call; flip the signedness of each typed load. [source-level]
- An argument masked at every use, the mask not factored -> the parameter itself is `u8` / `u16`; casts of an `int` parameter are computed once (func_0881C240, func_088A84B4). [source-level]
- The reverse: the raw register kept and passed on, a mask into a scratch register at each use, callers passing it unmasked -> an `s32` parameter cast at each use, `(u16) arg < N`, `tbl[(u16) arg]`; a narrow local keeps only the masked copy (func_088B6A80, func_08895644, func_088D777C). [source-level]
- A narrow value kept raw in a saved register and extended / masked at some uses only -> an `s32` local set from the narrow source, `(s16) v` / `(u8) v` written at the uses that extend; a narrow local extends once or into a temporary each time (func_088D2C14, func_088CDDAC, func_0883488C, func_088F1664). [source-level]
- An extension into the value's own register just before one use -> `s32` local and the statement `first = (s16) first;` (func_08818C94); raw in one saved register and extended in another -> `s32` parameter copied once into an `s16` local, a fresh `(s16) param` at the other use (func_088ADA44, func_088AAD58). [source-level]
- An extension right after a call into another register than ours -> an `int` local holding the narrowed result, `s32 id = (s16) f();` (func_088DCA10); a move after a call then an extension -> `s32 t` set by both arms, then `s8 r = t;` (func_0888FBD4). [source-level]
- A parameter copied unextended into a saved register and extended at each use -> an `s32` local assigned in its own statement, passed to `s16` parameters (func_088C1344). [source-level]
- A loop-invariant 16-bit id masked at each comparison -> compute it inside the loop in a `u32` local, narrowed by a separate `id &= 0xFFFF;` (func_088DDE20, func_088DDF94). [source-level?]
- Caller masks or extends a call result (or fails to) -> the callee's return type: extra mask / extension after the call -> callee returns `s32`; byte compare with no mask -> callee declared returning `u8`; `sum += f()` extended before an `s8` sum -> callee returns `s8` (func_08870E88, func_088CD964, func_0885CF9C). [source-level]
- A byte mask after a call tested against zero -> `f() == 0`, not `!f()`; or the callee declared `s32` and the call cast `(u8)` (func_0887BB48, func_0887CA4C). [source-level]
- The function's own return: extension in the return slot after a narrow sum -> return `s32`, keep the local narrow; no extension where ours has one -> return the narrow type (`s8`, `s16`) and work in the narrow variable; extension before each comparison but none at the return -> variable and return type both narrow (func_08872B40, func_08872CC0, func_088D72A4). [source-level]
- `x ? x : 0xFFFF` on a `u16` returned with no mask -> return `s32` (func_088CDC8C); a narrow function returning constants with a mask before the return -> every result in an `s32` local, one `return ret;` (func_0887959C); extension of a constant register in one case -> an `s8` result local in an `s8` function (func_088EFB18). [source-level]
- Unsigned compare where ours is signed (`sltiu` / `slti`) -> make the compared parameter unsigned (func_088A4654); a 16-bit mask followed by a signed compare where the original is unsigned -> an `unsigned int` local holding a `(u16)` cast, not a `u16` local (func_0888FCE4). [source-level]
- Compare-branch or add operands swapped, source order without effect -> type both values `char *` instead of `s32` (func_0888E218); first operand read as `u32`, second as `s32` (func_088C0468). [source-level?]
- Logical vs arithmetic shift of a narrow value -> cast before shifting, `(u32) *(u8 *) p >> 3`, `(u32) arg >> 1`, `(s32) ((u32) b >> 1)` for a signed compare after it; arithmetic halving of a `u16` is the plain `x = x >> 1` (`>>= 1` and `/= 2` differ) (func_08816F24, func_088952A4, func_088D92F8). [source-level]
- A field read unsigned for arithmetic and signed when passed as `s16` -> the field is `u16` (func_088198E4). [source-level]
- Float to unsigned: a test against 2147483648.0f around a conversion is the compiler's own `(u32) x`. Unsigned int to float (`bltz` / `srl 1` / `or` / `add.s`) comes from a `u16` / `u32` source without a cast (func_088CF2C8); copy the `u16` to a `u32` local first to avoid a second useless test (func_088D28DC); `(float) (u32) byte` (func_088CEAB8). [MIPS]
- A 16-bit value converted with the plain signed sequence -> mask an `int`, `K * (a & 0xFFFF)` (func_088D852C); converted unsigned, scaled, kept unmasked -> `u32` local, `v = (u16) (u32) (K * (float) v);` (func_088DADD8). [source-level?]
- A small constant passed to an `s8` parameter without extension -> keep it in an `s8` local (func_088226F0). [source-level]
- A byte mask on a byte already loaded unsigned, before an index -> a `u8` local read in the loop condition, `while ((c = *p) != 0xFF)`; mask in one branch only -> `s32` local and `(u8) id` in that branch (func_088701D8, func_08872444). [source-level]

- `#pragma opt_unroll_loops off` (after the speed pragma, ended by `reset`): a loop the original runs one pass at a time in a speed unit, e.g. an inline byte clear or a variable-count divide loop (func_088FB2B0, func_088F7620). [source-level]
- `#pragma opt_rebuildconditionals off`: a `return C;` that jumps straight to the epilogue with the value in its slot, dead instructions left after a jump, and 0/1 results kept as branches (`if (x == K) r = 1; else r = 0; return r;` with an `s32` `r`; a narrow result goes through an `s32` local first). - `#pragma opt_propagation off`: a constant index only half folded and kept for a second lookup (func_088DC1F0, not fully matched; it hurt another function). [source-level?]
- Inlining depth: helpers two or more levels deep are left as calls by default. `#pragma inline_depth(N)`, `#pragma inline_bottom_up on`, `-inline level=N` or `-inline bottomup` inline them (a three-level chain needs level 3 or `bottomup`); `inline_depth(smart)`, `auto_inline on`, `inline_max_size`, `inline_max_total_size`, `-inline on / all / auto / deferred` do not (func_088CF2C8, func_08901814). [source-level]
- `#pragma exceptions off`: needed for any tail call in C++ (func_088C6ADC, func_088DDE20). [source-level?]
- `__attribute__((aligned(16)))` on a local array or a structure type is accepted and sets the frame layout (func_088CEE68, func_088D1398). [source-level?]
- `asm { }` blocks inside C functions assemble MIPS and VFPU mnemonics with C pointer locals as base registers; `nop` and `.word` are accepted; branches to labels local to the block work, with a `nop` added after each unless the block starts with `.set noreorder` (func_088429EC, func_088D2E18).
